3. 실행 순서

BE 와 FE 를 각각 다른 터미널에서 띄운다.

터미널 A — 백엔드 (apimgr, 포트 8000)

cd apimgr
python -m venv .venv                              # 최초 1회
.venv/Scripts/python -m pip install -e ".[dev]"   # 최초 1회 (python-multipart 포함)
.venv/Scripts/python main.py                      # 진입점 main.run() — 포트 8000, reload 켜짐

동등한 명시 실행: .venv/Scripts/python -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload

터미널 B — 프런트 (hairsoui, 포트 3000)

cd hairsoui
npm install                                       # 최초 1회
npm run dev                                        # 포트 3000
⚠ 파일 업로드 의존성 assets 라우터가 multipart/form-data 를 쓰므로 python-multipart 가 필요하다. pip install -e ".[dev]" 에 포함되어 있다(누락 시 업로드·pytest 가 RuntimeError). apimgr/pyproject.toml

GenerationStatus (내부 10개)

CREATED · UPLOADING · SUBMITTED · QUEUED · PROCESSING · POST_PROCESSING · SUCCEEDED · FAILED · CANCELED · EXPIRED domain/enums.py:12

전이 규칙 — 타입별 상이

IMAGE : CREATED → SUBMITTED → (QUEUED) → PROCESSING → SUCCEEDED → (EXPIRED) (POST_PROCESSING 없음 — FFmpeg 후처리 불필요) VIDEO : CREATED → SUBMITTED → (QUEUED) → PROCESSING → POST_PROCESSING → SUCCEEDED → (EXPIRED) (다운로드·R2·FFmpeg 후처리 대기 단계 존재) 실패 : CREATED/SUBMITTED/PROCESSING/POST_PROCESSING → FAILED
핵심 규칙 (멱등·역행 안전) provider SUCCEEDED 매핑은 IMAGE=내부 SUCCEEDED 직행, VIDEO=내부 POST_PROCESSING(후처리 대기). 이미 SUCCEEDED 인 작업에 늦게 온 PROCESSING webhook 은 can_transition==False 로 무시(no-op)된다. domain/status_mapping.py:19 · state_machine.py:71

ProviderJobStatus (외부 4개)

PENDING · PROCESSING · SUCCEEDED · FAILED — provider 가 보고하는 값. domain/enums.py:47

6. API 방향

첫 구현은 DB migration 없이 in-memory/mock으로 시작한다. DB 적용을 위한 확장 DDL은 별도 migration 파일로만 준비한다.

구현 API역할
POST /api/v1/studio/projectsStudio 프로젝트 생성
POST /api/v1/studio/projects/{project_id}/draftscript/storyboard 초안 생성(MOCK 기본, OLLAMA 로컬 옵션)
PATCH /api/v1/studio/projects/{project_id}/draft사용자 편집본 저장
POST /api/v1/studio/projects/{project_id}/render기존 generation job 생성
GET /api/v1/studio/projects/{project_id}프로젝트와 render 상태 조회
응답 경계Studio API 응답에는 signed URL, 원본 storage key, provider raw payload를 넣지 않는다. 결과 참조는 output_asset_id 같은 내부 ID만 사용한다. Mock render는 작은 MP4 컨테이너 fixture로 asset 참조를 검증하고, SELF_HOSTED_WAN은 로컬 서버가 반환한 실제 MP4 바이트만 저장한다.
Render 입력이미지 없이 시작하는 Mock render는 내부 VideoGenerationInput.image_asset_id와 generation의 input_asset_id를 null로 둘 수 있다. SELF_HOSTED_WAN은 source asset이 있으면 BE 내부에서만 바이트를 읽어 multipart로 로컬 서버에 전달하고, URL·storage key·Base64는 전달하지 않는다.

7. FE 화면 방향

  • 첫 화면은 랜딩이 아니라 작업 화면으로 둔다.
  • 모바일은 단계형 단일 컬럼으로 구성한다.
  • 태블릿/데스크톱은 입력·초안 편집 영역과 9:16 preview 영역을 나란히 배치한다.
  • 스크립트와 storyboard는 생성 전 편집 가능해야 한다.
  • 실패 메시지는 기존 errorMessageView를 사용한다.
  • 고객 얼굴 원본이나 결과 URL은 browser storage에 저장하지 않는다.

8. 완료 기준

  1. /try는 제품 진입점에서 제외하고 필요 시 내부 회귀 데모로만 유지
  2. Studio Templates → Draft → Render → Result 흐름이 Mock으로 끝까지 진행
  3. DEFAULT_VIDEO_PROVIDER=SELF_HOSTED_WAN opt-in 시 로컬 /video/i2v 호환 서버가 반환한 MP4 바이트를 GENERATED_VIDEO로 저장
  4. PROMOTION_SHORT와 SALON_EVENT_PROMOTION이 모두 draft 생성 경로를 통과
  5. 생성 전 script/storyboard가 보이고 편집 가능
  6. 같은 프로젝트에서 반복 클릭해도 중복 render job을 만들지 않음
  7. Studio asset 참조는 위험한 문자열과 존재하지 않는 asset을 거부
  8. 소유자 없는 GENERATED_IMAGE는 Studio 입력으로 참조할 수 없음
  9. project/draft 텍스트의 URL·Base64·storage key 형태는 거부
  10. 실제 Provider, DB migration, FFmpeg, R2 없이 로컬 검증 가능
  11. FE는 외부 AI Provider를 직접 호출하지 않음
  12. OLLAMA draft provider를 켜도 호출은 BE 내부에서만 발생하고, 실패 시 Mock 초안으로 fallback
  13. BE 로그와 응답에 secret, signed URL, Base64, 원본 이미지 URL 미노출
